# Only live-mask evidence banks confidence

The search must prove offsets for the condition the machine actually runs in, and Curve Optimizer faults on one core depend on what every other core is doing. Isolated slots (peers at stock) make a failure attributable but describe a machine that never exists, so their passes are hypotheses only; a slot banks clean time and advances a core's phase solely under the live mask (peers at their baselines). Attribution of a failure that names no core goes to the hunt instead of to isolated re-testing.

## Considered options

- Isolated per-core search with all peers at stock, the classic CoreCycler method. Rejected: session 7 on a 7800X3D crashed only with every offset resident while idle, and the isolated hunt reported "no culprit" after removing the failing condition.
- Live-only with no isolated slots at all. Rejected: attribution of an unnamed failure then has no deterministic tool; the hunt keeps isolation as a bisection step, never as evidence.

## Consequences

Offsets found this way are conditional on the whole vector, so a change to any core's baseline invalidates the bank of every core in that context, and the report is the surviving vector, not a set of independent per-core answers.
